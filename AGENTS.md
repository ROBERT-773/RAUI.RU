# Правила разработки RAUI.RU

Работайте в существующем checkout RAUI.RU и опубликованной облачной среде.
Не создавайте отдельный worktree без запроса пользователя. Изменения выполняйте
в отдельной feature-ветке; master и production напрямую не изменяйте.
Подготовьте pull request, не выполняйте merge или deploy без отдельного запроса.

Перед изменениями кратко опишите план и структуру затронутых файлов.
Затем выполняйте работу самостоятельно до завершения; не запрашивайте
подтверждение для обычных обратимых действий в согласованном объёме.
Блокирующие требования и отсутствующие секреты уточняйте; секретные значения
не просите в чате и не добавляйте в репозиторий или логи.

Foundation ограничен инфраструктурным каркасом. Не добавляйте бизнес-функции
без согласованного задания. Не выдумывайте детали ТЗ: сверяйтесь с предоставленным
документом; README описывает только реализованное состояние.

Используйте pnpm 10.0.0, Node 24 и strict TypeScript. Обновляйте pnpm-lock.yaml
вместе с зависимостями; CI устанавливает зависимости с --frozen-lockfile.
Серверные секреты не должны попадать в web-клиент. Compose — только локальная
инфраструктура. Сохраняйте пользовательские изменения и существующие .env.

Обязательные проверки из корня: pnpm lint, pnpm typecheck, pnpm test, pnpm build.
Для изменений сервисов дополнительно запустите infra и production smoke:
pnpm infra:up; pnpm --filter @raui/api start; pnpm --filter @raui/web start;
pnpm smoke. Приложения запускаются в отдельных терминалах.
Исправьте ошибки проверок. Различайте пройденные, упавшие и неисполненные проверки;
не заменяйте настоящие проверки заглушками и не скрывайте ошибки.

В конце отчитайтесь: что создано, что проверено, какие команды проходят,
ограничения, ссылка на PR и рекомендуемые следующие шаги.
