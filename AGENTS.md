# Правила разработки RAUI.RU

Работайте в существующем checkout RAUI.RU и опубликованной облачной среде.
Не создавайте отдельный worktree без запроса пользователя. Изменения выполняйте
в отдельной feature-ветке; master и production напрямую не изменяйте.
Подготовьте pull request, не выполняйте merge или deploy без отдельного запроса.

Перед изменениями кратко опишите план и структуру затронутых файлов.
Затем выполняйте работу самостоятельно до завершения; не запрашивайте
подтверждение для обычных обратимых действий в согласованном объёме.
Блокирующие требования и отсутствующие секреты уточняйте; секретные значения
не просите в чате и не добавляйте в репозиторий или логи.

## Авторитетные документы

Перед началом любого этапа обязательно прочитайте:

- `docs/RAUI_MASTER_EXECUTION_PLAN.md` — порядок этапов, границы и exit criteria;
- `docs/RAUI_TZ_v1.0.md` — техническое задание продукта;
- GitHub Issue текущего этапа — детальная рабочая постановка.

Не выдумывайте требования, которых нет в этих источниках. При конфликте:

1. безопасность и целостность данных имеют приоритет;
2. затем техническое задание;
3. затем план этапа;
4. затем текст рабочей задачи.

Не переходите к следующему этапу, пока текущий не завершён и не принят.

## Технические правила

Используйте pnpm 10.0.0, Node 24 и strict TypeScript. Обновляйте pnpm-lock.yaml
вместе с зависимостями; CI устанавливает зависимости с --frozen-lockfile.
Серверные секреты не должны попадать в web-клиент. Compose — только локальная
инфраструктура. Сохраняйте пользовательские изменения и существующие .env.

Все изменения БД выполняйте только через версионируемые миграции.
Предпочитайте backward-compatible стратегию: expand -> backfill -> switch -> contract.
Не храните крупные бинарные файлы в PostgreSQL.
Внешние провайдеры (карты, SMS, email, payments, AI, object storage) держите за адаптерами/интерфейсами.

## Обязательные проверки

Из корня:

- `pnpm lint`
- `pnpm typecheck`
- `pnpm test`
- `pnpm build`

Для изменений сервисов дополнительно:

- `pnpm infra:up`
- production smoke для API и web
- `pnpm smoke`
- `pnpm infra:down`

Добавляйте unit/integration/API/E2E тесты по мере появления соответствующей функциональности.
Не заменяйте настоящие проверки заглушками и не скрывайте ошибки.

## Завершение работы

В конце отчитайтесь:

- что создано;
- какие миграции добавлены;
- что проверено;
- какие команды проходят;
- ограничения/риски;
- ссылка на PR;
- rollback/forward-fix notes;
- рекомендуемые следующие шаги.

После выполнения exit criteria текущего этапа остановитесь и не переходите к следующему без отдельной команды.

## Этапы после Foundation

Сверяйтесь с `docs/RAUI_MASTER_EXECUTION_PLAN.md` и `docs/RAUI_TZ_v1.0.md`.
Работайте только в явно запрошенном этапе. Для core changes обязательны также
`pnpm test:integration` и миграционные проверки; см. `docs/PHASE_2_CORE.md` и
`docs/MIGRATIONS.md`. Не меняйте ранее применённые SQL migration files.
Применяйте миграции только к локальной DB в cloud task; production changes
требуют отдельного задания. Обновляйте OpenAPI вместе с REST контрактами.
После этапа подготовьте PR и остановитесь; следующий этап не начинается автоматически.
