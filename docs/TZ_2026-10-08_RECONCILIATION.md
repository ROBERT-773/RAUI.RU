## Очередь доработок

1. Сохранить источник и эту сверку. Готовые PR интегрировать отдельным разрешённым
   действием: сначала исправление имени обязательной CI-проверки #47; #54 перед #55;
   #53 перед SMTP #61. Не ослаблять защиту ветки.
2. Подготовить региональный контракт: конфигурации четырёх регионов, правила
   геосправочника, совместимость существующих адресов и поисковых URL, региональные
   фильтры и API. Это следующий продуктовый блок; данная сверка его не реализует.
3. Закрыть публичную/приватную границу данных, версионирование согласий и матрицу
   новых ролей; затем обязательную 2FA. Для схемы использовать новые миграции,
   сохранённые SQL-файлы не менять.
4. По утверждённым региональным и ролевым контрактам доработать поиск, мастера
   публикации и кабинеты, включая пустые/ошибочные/недоступные состояния и мобильные
   сценарии.
5. Реализовать и принять уведомления сохранённых поисков и исходящие публикации
   по договорам площадок. Отсутствующие credentials вводятся через защищённые
   настройки, не через чат.
6. Отдельно подготовить архитектурную спецификацию миграции к требуемому стеку:
   границы сервисов, источник истины, идентичность, события, совместимость API,
   наблюдаемость и обратимый rollout. Возможны поэтапное выделение сервисов либо
   полная замена; первое снижает риск для уже работающих функций. Выбор и план
   нельзя считать утверждёнными этим документом.
7. Выполнить фактические инфраструктурные/provider/security/load/DR приёмки
   #40–46 и новые MVP-чек-листы. Только после этого решать вопрос production.

## Ограничения этой задачи

Изменены только документы. Новое ТЗ зафиксировано как вход для доработки;
прежний стек, API, роли, schema, конфигурация сервера и feature flags этим PR
не меняются. Противоречия сохранены в таблице для дальнейших явных решений.
Новая архитектура, оценка трудозатрат и юридическая часть не объявляются принятыми.

Rollback: откатить документационный PR. Это не откатывает прежние функции и
не удаляет исходное пользовательское вложение. Следующий результат — отдельный
региональный дизайн и проверяемый план доработки существующего приложения.
