# Региональный поиск: Москва и Московская область

Регион задаётся явно через `address.regionCode` при создании или изменении
объекта API. Значение проверяется по конфигурационному справочнику регионов.
Поле необязательное: существующие адреса остаются с `region_code = NULL`.
Название населённого пункта и координаты не используются для угадывания региона.
Назначение региона пользователем не подтверждает административную принадлежность
адреса; проверенный геопровайдер и границы подключаются отдельно.

Поиск принимает необязательный `regionCode`. Выбранный регион применяется
одновременно в OpenSearch и в PostgreSQL при проверке актуальности результатов.
Это действует для списка, карты и выбранных объектов. Адреса без назначения
видны в поиске без региона и исключаются при выборе конкретного региона.
Сохранённые поиски и курсоры учитывают регион; старые запросы без него совместимы.

Интерфейс получает варианты из `/v1/regions`. При изменении региона очищаются
населённый пункт, район, метро, округ, направление трассы, область карты,
выделение и курсор; остальные параметры поиска сохраняются. Ошибка загрузки
справочника показана пользователю. Форма создания объявления в этом изменении
не добавляется: регион назначается через существующее API объекта.

## Миграция и запуск

Миграция `013_region_search.sql` добавляет nullable поле адреса и новый столбец
в конец публичной поисковой проекции. Ранее применённые миграции не изменяются.
Обновление адреса использует существующую очередь переиндексации.

Порядок при согласованном развёртывании:

1. Применить миграции штатной командой `pnpm db:migrate`.
2. Собрать API/web, включая YAML справочника из PR #66.
3. Запустить обновлённый поисковый worker: его initialization добавляет keyword
   mapping `region_code` в существующий индекс до записи документов.
4. Выполнить штатный reindex/reconciliation и проверить региональные запросы.
5. Назначать регионы старым адресам только после проверки данных.

Нельзя запускать новый worker до миграции БД. Аддитивный mapping не заменяет
полную переиндексацию: ранее созданные документы могут ещё не иметь региона.
Старые объявления не получают регион автоматически.

Rollback: восстановить предыдущую версию приложения, оставив nullable столбец
и дополнительный mapping. Не удалять сохранённые назначения региона из БД.
Forward-fix: исправить подтверждённое назначение адреса и обработать очередь;
при неполном индексе выполнить reindex. Этот PR не развёртывает изменения.
