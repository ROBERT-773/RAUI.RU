# Проверка XML из кабинета

Независимый агент подключает выгрузку в личном кабинете. У агентства и
застройщика ссылками управляет владелец или администратор организации. Для
каждой площадки предусмотрено отдельное поле. Запуск проверки сохраняет
отчёт, к которому можно вернуться после повторного входа.

## Подключение выгрузки

1. Откройте «Мои XML-выгрузки» или «XML-выгрузки организации».
2. Вставьте HTTPS-ссылку на XML из вашей учётной системы в строку Яндекс Недвижимости, Авито, Циана или Домклика. Заполняйте только нужные строки.
3. Нажмите «Проверить». В этой же строке появятся число проверенных объектов, число успешных записей и ошибки. Кнопка «Посмотреть ошибки» открывает причины по конкретным объявлениям.

Кнопка «Проверить ещё раз» использует сохранённый адрес. Чтобы заменить
ссылку, вставьте новую в строку той же площадки. В кабинете отображается
только имя хоста. Если доступ к хосту ещё не разрешён, администратор может
добавить его в серверную настройку `FEED_ALLOWED_HOSTS`.

Предварительная проверка доступна до допуска к публикации. Её счётчики
показывают результат проверки файла. Публичные объявления при этом не создаются.

Циан допускает UTF-8 и Windows-1251. Яндекс Недвижимость указывает UTF-8
для YRL. [Технические требования Циана](https://www.cian.ru/xml_import/doc/)
и [требования к YRL](https://yandex.ru/support/realty/ru/feed/content-requirements).

## Как включить автопубликацию

Администратор открывает «Автопубликация из XML» в служебном кабинете. Кнопка
«Разрешить автопубликацию» доступна, когда последняя проверка текущей ссылки
нашла хотя бы один подходящий объект. После разрешения портал сразу ставит
первую загрузку в очередь. Затем он проверяет источник каждый час. При замене
ссылки владельцем потребуется проверить новый файл и снова выдать разрешение.

Если сотрудник, подключивший ссылку, потерял доступ к агентству, действующий
владелец или администратор организации нажимает «Проверить ещё раз». После
успешной проверки он сможет выступать ответственным за последующие загрузки.
Владельцы ранее размещённых объявлений сохраняются.

Владелец видит в строке площадки статус допуска и отдельный отчёт о публикации.
В отчёте указано, сколько объявлений создано, обновлено, осталось без изменений
и требует исправления. По идентификатору объекта портал находит прежнюю карточку
и обновляет цену и фотографии. Если новое фото не удалось принять, у уже
опубликованной карточки сохраняются прежние цена и галерея. Другие корректные
объекты из файла могут быть опубликованы.

Для ручной подачи требуется минимум пять фотографий. Для одобренного XML
достаточно одной обработанной фотографии объекта. Администратор задаёт хосты
изображений через `FEED_MEDIA_ALLOWED_HOSTS`. По умолчанию используются хосты
самого XML из `FEED_ALLOWED_HOSTS`.

## Прежний портал

В архивной копии раздел кабинета описан в `captcha/application/views/page/xml.php`.
Агент указывал ссылку в профиле и получал результат подключения. Входящий XML
обрабатывали контроллер `captcha/application/controllers/xml.php` и плановый
обработчик `captcha/application/models/cron/xml_model.php`. `YRL.php` формировал
исходящую выгрузку в формате Яндекс Недвижимости.

Исторический файл содержал 2690 предложений и занимал 7 389 168 байт.
Координаты отсутствовали. При проверке такого объекта RAUI использует настроенный
геокодер и принимает единственное точное совпадение адреса в указанном городе.
Если координаты определить не удалось, агент видит причину у объявления.

## Обновление базы и откат

Миграция `037_personal_xml_sources.sql` добавляет личные источники и сохраняет
владельцев и историю существующих организационных выгрузок. Для каждой
площадки разрешена одна управляемая ссылка на владельца. Применить миграцию
перед обновлением API и обработчиков очереди. При откате приложения остановить
обработку личных выгрузок, сохранить схему и историю и возобновить обработку
после установки исправленной версии.

Миграция `038_trusted_xml_publication.sql` добавляет допуск к публикации,
связь загрузки с версией ссылки и учёт фотографий. После миграции всем прежним
источникам требуется явное разрешение администратора. Порядок установки —
миграция, затем API и обработчики очереди. Для отката отозвать выданные допуски,
остановить обработчики и дождаться завершения активных операций перед возвратом
к прежней версии приложения. Сохранить схему, опубликованные карточки и файлы
для следующего запуска исправленной версии.
