# Региональный справочник

Первый функциональный блок [#65](https://github.com/ROBERT-773/RAUI.RU/issues/65)
по новому ТЗ. По уточнению пользователя стартуют только **Москва** и
**Московская область**. СПб и ЛО остаются следующим расширением.

Конфигурации: `apps/api/config/regions/moscow.yaml` и `moscow_oblast.yaml`.
API: публичные `GET /v1/regions` (`items`) и
`GET /v1/regions/:code/filters` (метаданные региона).
Через существующий web proxy пути доступны под `/api/v1/regions`.
OpenAPI описывает ответы, ошибки 400 для некорректного кода и 404 для неизвестного.
Контракт этих маршрутов остаётся справочным.

`search_entities`, `metro_available` и `directions_available` описывают модель
региона, а не подтверждают подключение источников данных. Каждый ответ имеет
`data_status: catalogue_only`. Проверенные границы ещё не привязаны:
`geo_bounds: null`. Назначение региона адресу, фильтрация индекса и выбор
региона в интерфейсе описаны отдельно в [региональном поиске](REGIONAL_SEARCH.md).
Геосправочники метро/районов, autocomplete и подтверждённые административные
границы ещё не подключены. Метаданные справочника не подтверждают наличие
объявлений и геоданных для всех регионов.

## Расширение

Добавить UTF-8 `.yaml` в конфигурационный каталог, с кодом вида
`[a-z][a-z0-9_]{0,49}`. Поля: `code`, `name`, `type` (`city`/`oblast`),
`search_entities`, `metro_available`, `directions_available`, `timezone`,
`currency: RUB`, `geo_bounds` (проверенный прямоугольник либо null).
Допустимы сущности `okrug`, `district`, `metro`, `street`, `house`, `locality`,
`direction`. Метро/направления должны согласовываться с флагами.

Код продукта менять не требуется. Пересобрать приложение и отдельно разрешённым
действием обновить runtime: конфигурация загружается один раз при запуске.
Нельзя копировать примерные границы из демонстрационного YAML как официальные.

Парсер использует pinned `yaml` с core schema, запрещает aliases, дубли ключей,
неизвестные поля, повторные коды/сущности, неверные координаты и часовые пояса.
Пределы: 100 регионов и 64 KiB на запись. Символические ссылки на другие файлы
не принимаются. Ошибки конфигурации очищены от содержимого; запуск при ошибке
прерывается. HTTP-код не используется в пути файловой системы. Ответы отделены
от внутренней конфигурации, чтобы запрос не мог изменить последующий результат.

## Сборка и приёмка

API build валидирует и копирует только YAML-записи в `dist/config/regions`;
unit/integration compilation — в `.cache/test/config/regions`.
Устаревшие записи выходного каталога удаляются перед копированием.
Runtime packaging из PR #62 переносит API dist; после интеграции нужен новый
образ и повторная проверка YAML/dependency closure. Ранее проверенный образ
#62 не содержит этот новый функциональный блок.

Проверять без пользовательской сессии: список содержит только `moscow` и
`moscow_oblast`, обе конфигурации доступны, неизвестный код возвращает 404,
некорректный — 400. Проверять также OpenAPI и наличие YAML в собранном API.
Адресная принадлежность, миграция 013, индексация и выбор региона в UI реализованы
в отдельном блоке [регионального поиска](REGIONAL_SEARCH.md). Это не подтверждает
географическую точность присвоения: существующие адреса нельзя автоматически
назначать региону по неподтверждённой строке. Границы и справочники провайдеров
остаются отдельной задачей.

Миграций, провайдерных вызовов и установки на VPS в этой задаче нет.
Rollback: откатить PR и пересобрать API; схема БД и существующие URL совместимы.
