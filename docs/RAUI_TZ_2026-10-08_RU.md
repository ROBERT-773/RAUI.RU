## 1. Цели и границы проекта

### 1.1. Цель

Создать публичный портал недвижимости, функционально сопоставимый с ЦИАН, но:

- с собственным современным дизайном;
- с фокусом на конкретные регионы (Москва, МО, СПб, ЛО);
- с возможностью расширения на новые регионы без переписывания ядра;
- с лишними функциями, отложенными на будущее (feature flags).

### 1.2. Границы MVP

**Входит в MVP:**

- Публичный каталог с поиском, фильтрами и картой.
- Карточка объекта с медиа, характеристиками и контактами.
- Регистрация и личный кабинет (покупатель, собственник, агент).
- Публикация объявлений (агентство + частные лица).
- Модерация объявлений.
- Внутренний кабинет агентства (агент, руководитель).
- Базовые интеграции с ЦИАН, Домклик, Авито (адаптеры).
- Аналитика и отчёты.

**Не входит в MVP (заложено как расширение):**

- Ипотечный калькулятор с банками.
- Онлайн-бронирование просмотров.
- Виртуальные туры 360°.
- Платная реклама внутри портала.
- Мобильные приложения iOS/Android (в MVP — адаптивный веб).

### 1.3. Ключевые метрики успеха

- Время загрузки страницы: LCP ≤ 2,5 с на мобильной сети.
- Время отклика поиска: p95 ≤ 500 мс.
- Конверсия в заявку: измеряется, целевое значение — после пилота.
- Доля отклонённых модерацией объявлений: ≤ 10%.

## 2. Регионы и география

### 2.1. Стартовые регионы

| Регион                | Субъекты поиска                                | Особенности                               |
| --------------------- | ---------------------------------------------- | ----------------------------------------- |
| Москва                | Административный округ, район, метро           | Пешая и транспортная доступность до метро |
| Московская область    | Городской округ, населённый пункт, направление | Удалённость от МКАД, транспорт            |
| Санкт-Петербург       | Район, метро                                   | Пешая и транспортная доступность          |
| Ленинградская область | Район, населённый пункт, направление           | Удалённость от КАД                        |

### 2.2. Расширяемость регионов

Регион описывается конфигурацией, а не кодом:

```yaml
region:
  code: moscow
  name: Москва
  type: city
  geo_bounds: { min_lat: 55.5, max_lat: 56.0, min_lon: 37.3, max_lon: 37.9 }
  search_entities: [okrug, district, metro, street, house]
  metro_available: true
  directions_available: false
  timezone: Europe/Moscow
  currency: RUB
```

Добавление региона = добавление YAML-конфига + наполнение справочника. Код не меняется.

### 2.3. Геосправочник

- Источник: обновляемый геосервис (Яндекс Geocoder / DaData / ФИАС).
- Хранение: нормализованный адрес + координаты + уровень точности (точная / округлённая / скрытая).
- Метро, районы, границы — из справочника, обновляются по расписанию.
- Публичная точка может быть округлена по согласию собственника (для частных домов).

## 3. Типы недвижимости и категории

### 3.1. Категории

### 3.2. Тип сделки

- Продажа
- Аренда (долгосрочная)
- Аренда (посуточная) — заложено, не в MVP
- Аренда с выкупом — заложено

### 3.3. Гибкие атрибуты

Для каждой категории — свой набор полей, хранится в JSONB + JSON Schema валидация.

**Пример: квартира**

- Комнат: число
- Площадь общая / жилая / кухня
- Этаж / этажей в доме
- Год постройки
- Тип дома (панель, кирпич, монолит, сталинка, хрущёвка)
- Ремонт (косметический, европейский, дизайнерский, без ремонта)
- Санузел (раздельный, совмещённый, N санузлов)
- Балкон / лоджия
- Лифт (пассажирский, грузовой)
- Парковка
- Отделка
- Мебель
- Техника

**Пример: дом**

- Площадь дома / участка
- Этажей
- Материал стен (кирпич, дерево, газобетон, брус)
- Год постройки
- Отопление (газ, электричество, твёрдое топливо)
- Вода (центральная, скважина, колодец)
- Канализация (центральная, септик)
- Газ (магистральный, баллон)
- Электричество (кВт)
- Коммуникации
- Расстояние до города

## 5. Регистрация и кабинеты

### 5.1. Регистрация

**Способы:**

- Email + пароль
- Телефон + SMS-код
- Социальный вход (Яндекс, VK, Google) — опционально
- Двухфакторная аутентификация для агентов и администраторов

**Обязательные шаги:**

1. Ввод email/телефона.
2. Подтверждение (письмо/код).
3. Согласие с офертой и политикой ПДн.
4. Согласие на обработку персональных данных (152-ФЗ).

### 5.2. Кабинет покупателя/арендатора

- Избранное (объекты, поиски).
- Сохранённые поиски с уведомлениями (email, push).
- История просмотров.
- Мои заявки (статус, ответы).
- Настройки уведомлений.
- Управление профилем.

### 5.3. Кабинет собственника

- Мои объявления (черновики, активные, архив).
- Статистика просмотров и звонков.
- Управление ценой и параметрами.
- Продвижение объявления (заложено).
- Мои заявки от покупателей.
- Согласия и права на публикацию.

### 5.4. Кабинет агента

- Входящие заявки.
- Задачи на день.
- Создание объекта (пошаговый мастер).
- Публикация на каналы.
- Клиентская база.
- Дневной отчёт.

### 5.5. Кабинет руководителя

- Очередь ошибок публикаций.
- SLA-дашборд.
- Аналитика продаж и лидов.
- Управление ролями и доступами.
- Справочники и регламенты.

### 5.6. Кабинет модератора

- Очередь объявлений на проверку.
- Проверка фото, описания, цены.
- Отклонение с причиной.
- История решений.
- Автоматические проверки (дубли, запрещённые слова, контакты в тексте).

## 6. Фильтры и поиск

### 6.1. Основные фильтры

**География:**

- Регион (Москва, МО, СПб, ЛО).
- Район / округ.
- Метро (для Москвы и СПб).
- Направление (для МО и ЛО).
- Удалённость от центра / МКАД / КАД.
- Радиус поиска на карте.

**Сделка:**

- Тип: продажа / аренда.
- Цена от и до.
- Валюта (RUB).
- Период аренды (месяц).

**Объект:**

- Категория недвижимости.
- Тип объекта (студия, 1-к, 2-к…).
- Комнат: студия, 1, 2, 3, 4, 5+.
- Площадь общая от и до.
- Площадь жилая от и до.
- Площадь кухни от и до.
- Этаж от и до.
- Этажей в доме от и до.
- Год постройки от и до.
- Тип дома.
- Ремонт.
- Санузел.
- Балкон / лоджия.
- Лифт.
- Парковка.
- Мебель.
- Техника.

**Дополнительно:**

- Только с фото.
- Только с видео.
- Только с планировкой.
- Без посредников.
- От застройщика.
- Новостройка.
- Сдача / продажа от собственника.

### 6.2. Сортировка

- По цене (возрастание / убывание).
- По площади.
- По дате публикации.
- По дате обновления.
- По популярности.
- По удалённости от метро.

### 6.3. Карта

- Кластеризация маркеров при отдалении.
- Подгрузка объектов при приближении.
- Рисование области поиска (полигон).
- Радиус поиска.
- Синхронизация с фильтрами списка.

### 6.4. Поиск по тексту

- Полнотекстовый поиск по описанию и адресу (Elasticsearch, русский анализатор).
- Автодополнение адресов (DaData / Яндекс).
- Поиск по ID объявления.
- Исправление опечаток (error-tolerant).

### 6.5. Сохранённые поиски

- Пользователь сохраняет набор фильтров.
- Уведомления о новых объектах (email, push).
- Частота уведомлений настраивается.

## 8. Публикация и модерация

### 8.1. Процесс публикации

1. Пользователь создаёт черновик.
2. Заполняет обязательные поля.
3. Загружает фото (минимум N, максимум M).
4. Проходит автопроверку (дубли, запрещённые слова, контакты в тексте).
5. Отправляет на модерацию.
6. Модератор одобряет / отклоняет с причиной.
7. Публикация появляется в каталоге.
8. Агентство дополнительно публикует на ЦИАН/Домклик/Авито через адаптеры.

### 8.2. Автопроверки

- Дубли по адресу + площади + цене.
- Контакты в тексте описания (телефон, email, мессенджеры).
- Запрещённые слова (мат, спам, реклама).
- Некорректная цена (слишком низкая / высокая).
- Несоответствие площади и категории.
- Орфография и пунктуация.

### 8.3. Причины отклонения

- Недостоверная информация.
- Некорректные фото.
- Контакты в описании.
- Дубль.
- Нарушение правил портала.
- Другое (с комментарием).

### 8.4. Продвижение (заложено, не в MVP)

- Поднятие в поиске.
- Выделение цветом.
- Показ на главной.
- Приоритетное размещение.

## 9. Архитектура и стек

### 9.1. Архитектура

Микросервисная с API Gateway. На старте — 8–12 сервисов с возможностью масштабирования.

**Слои:**

- Клиентский: web (SSR + SPA), мобильный адаптив, кабинеты.
- API Gateway: маршрутизация, JWT, rate limiting, версионирование.
- Сервисный: доменные микросервисы.
- Данные: PostgreSQL, Elasticsearch, Redis, S3, ClickHouse, Kafka.
- Инфраструктура: Kubernetes, CI/CD, мониторинг.

### 9.2. Стек

| Слой           | Технология                                   |
| -------------- | -------------------------------------------- |
| Backend        | Java 21 + Spring Boot 3 или Node.js (NestJS) |
| API Gateway    | Spring Cloud Gateway / Kong                  |
| Поиск          | Elasticsearch 8+                             |
| БД             | PostgreSQL 16+                               |
| Кэш            | Redis 7+                                     |
| Очереди        | Apache Kafka                                 |
| Аналитика      | ClickHouse                                   |
| Frontend       | Next.js 15 (App Router)                      |
| Карты          | Яндекс Карты API                             |
| Аутентификация | Keycloak                                     |
| Медиа          | S3 + CDN                                     |
| IaC            | Terraform + Helm                             |
| CI/CD          | GitHub Actions + ArgoCD                      |

### 9.3. Микросервисы

| Сервис                 | Ответственность              |
| ---------------------- | ---------------------------- |
| `listing-service`      | Объекты и предложения        |
| `search-service`       | Поиск и геопоиск             |

| `moderation-service`   | Модерация объявлений         |

| `analytics-service`    | События и метрики            |
| `geo-service`          | Геосправочник и нормализация |
| `audit-service`        | Аудит                        |

## 10. Модель данных

### 10.1. Основные сущности

**User:** id, email, phone, password_hash, role, status, created_at, updated_at.

**Region:** code, name, type, geo_bounds, search_entities, timezone, currency, config.

**Property:** id, address_raw, address_normalized, geo_lat, geo_lon, geo_precision, region_code, okrug, district, metro_ids, direction, category, category_fields (JSONB), status, created_by, created_at, updated_at, archived_at.

**Offer:** id, property_id, deal_type, price, currency, price_period, commission_terms, owner_user_id, responsible_user_id, status, published_version, created_at, updated_at.

**MediaAsset:** id, property_id, offer_id, kind (photo/video/plan/document), storage_key, mime, size, width, height, order_index, is_public, alt_text, hash, created_at.

**Publication:** id, offer_id, channel, account_id, external_id, external_url, status, mapping_version_id, sent_snapshot_id, last_sent_at, last_confirmed_at, last_error_code, last_error_text, responsible_user_id.

**Lead:** id, user_id, contact_id, property_id, offer_id, funnel, source, utm, message, status, assigned_to, first_response_at, created_at.

**ModerationTask:** id, offer_id, status, moderator_id, reason_code, comment, created_at, resolved_at.

**Favorite:** id, user_id, entity_type, entity_id, created_at.

**SavedSearch:** id, user_id, name, filters (JSONB), notify_frequency, created_at, last_notified_at.

**Consent:** id, user_id, scope, granted_at, revoked_at, document_ref.

**AuditEvent:** id, entity_type, entity_id, action, actor_id, before, after, reason, created_at.

### 10.2. Гибкие атрибуты

`category_fields` — JSONB с валидацией по JSON Schema для каждой категории.

### 10.3. Поисковый индекс

Elasticsearch-маппинг: title, description, category, deal_type, price, region, district, metro_ids, location (geo_point), rooms, area, floor, floors_total, year_built, features, status, created_at, updated_at.

## 12. UX/UI и дизайн

### 12.1. Принципы дизайна

- Современный, чистый, не копирующий ЦИАН.
- Мобильный приоритет (mobile-first).
- Крупные touch-targets (≥ 44×44 px).
- Быстрая загрузка (Core Web Vitals).
- Доступность (WCAG 2.1 AA).

### 12.2. Дизайн-система

- **Цвета:** основная палитра (нейтральная + акцент), семантические (успех/ошибка/предупреждение).
- **Типографика:** Inter / Manrope, масштаб, межстрочные.
- **Компоненты:** карточка, фильтр, карта, форма, календарь, уведомление, таблица, модальное окно.
- **Иконки:** собственный набор или адаптация открытой библиотеки.
- **Тёмная тема:** опционально, заложено.

### 12.3. Ключевые экраны

**Публичные:**

- Главная (поиск, регионы, популярные фильтры, блок собственнику).
- Каталог (список + карта).
- Карточка объекта.
- Страницы услуг (продажа, аренда, новостройки, загородная, коммерция).
- Страницы регионов и районов (только наполненные).
- О компании, команда, контакты, юридические страницы.

**Кабинеты:**

- Покупателя.
- Собственника.
- Агента.
- Руководителя.
- Модератора.

### 12.4. Состояния

Для каждого экрана: пустое, загрузка, ошибка, нет прав, успех.

## 13. Безопасность и ПДн

- OAuth 2.0 / OIDC (Keycloak), JWT, 2FA для сотрудников.
- RBAC: роли и права.
- TLS 1.3, шифрование чувствительных полей (AES-256).
- Секреты в Vault / Secrets Manager.
- 152-ФЗ: согласия, право на забвение, удаление.
- Аудит всех критичных изменений.
- Логи без ПДн, структурированные, с trace_id.
- WAF, rate limiting, сканирование уязвимостей.
- Сетевая изоляция: private subnets для БД.

## 14. DevOps и инфраструктура

### 14.1. Окружения

- local (Docker Compose).
- dev (интеграция, mock-каналы).
- stage (анонимизированные данные).
- prod (реальные данные).

### 14.2. CI/CD

Push → Lint → Unit → Build → Scan → Integration → Deploy dev → E2E → Approval → Stage → Smoke → Approval → Prod.

Инструменты: GitHub Actions, ArgoCD, Helm, Terraform.

### 14.3. Мониторинг

- Prometheus + Grafana (метрики).
- Loki / ELK (логи).
- OpenTelemetry + Jaeger (трейсинг).
- Алерты: ошибка выгрузки ≤ 15 мин, пустой фид, рост `unknown`.
- SLO: ядро 99,5%, сайт 99,9%, p95 поиска ≤ 500 мс.

### 14.4. Бэкапы

- RPO ≤ 15 минут, RTO ≤ 4 часа.
- Ежемесячная проверка восстановления.
